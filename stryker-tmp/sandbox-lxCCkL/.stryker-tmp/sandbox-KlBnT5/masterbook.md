## 1. PROJECT IDENTITY

### What This Is
AlgoMind is a scalable, AI-driven technical interviewing platform designed to simulate human-led coding interviews. It aims to prepare candidates for high-stress FAANG-style interviews by evaluating them on 8 cognitive dimensions rather than simply checking if code compiles. It features a full voice mode with interruptions, a knowledge graph for skill tracking, and enterprise employer dashboards.

### Current Status
Production-ready with minor tech debt. Pre-audit fixes removed stale cache evictions and telemetry bypasses.

### Production Readiness Score
**85/100 (Strong)**
The codebase is exceptionally well-structured, utilizing strict domains and excellent state machine patterns for complex voice interactions. Upstash rate limiting and circuit breakers provide solid resilience. Weaknesses include relying on a public Piston API for code execution and slightly duplicated frontend skeleton loading states.

## 2. COMPLETE ARCHITECTURE

### Architecture Pattern
**Serverless Monolith with Edge Enhancements.**
The platform leverages Next.js App Router for both frontend and backend API endpoints. Supabase provides the persistent data layer (Postgres + pgvector) and real-time subscriptions, while Upstash Redis handles high-throughput ephemeral data (rate limits, circuit breakers). Heavy background tasks (like calculating cohort analytics) are offloaded to Inngest. Voice processing is a hybrid client-server model: VAD runs on the client to ensure low-latency interruption detection, while the server handles LLM generation and TTS streaming.

### Request Lifecycle (Interview Session)
1. User hits `/interview?problemId=123`.
2. Server components fetch user profile, problem constraints, and RAG context via `src/app/interview/page.tsx`.
3. Client mounts `<InterviewSession>` which initializes `state-machine.ts`.
4. User speaks; client-side VAD detects speech end.
5. Client sends audio chunk or transcript to `/api/interview/chat`.
6. API routes through `src/lib/ai/client.ts` to Gemini.
7. Streamed response is chunked by `text-chunker.ts` and sent to Polly for TTS.
8. Client plays audio. Upon completion, `save-session.ts` writes history to Supabase.

### Service Boundaries
- `src/lib/ai`: Abstracted LLM provider logic (Bedrock, Gemini, Groq).
- `src/lib/voice`: Audio stream processing, TTS, and interruption management.
- `src/lib/assessment`: Core logic for grading and analyzing transcripts.
- `src/components`: Strictly presentation and client state logic.

## 5. AI & API COMPLETE REFERENCE

### AI Models In Use
#### Gemini 1.5 Flash / Pro
- **Provider:** Google AI Studio
- **Purpose:** Core conversation agent. Fast latency makes it ideal for real-time voice interactions.
- **Estimated cost exposure:** Low (Free tier models configured via env vars).

#### Polly TTS
- **Provider:** AWS
- **Purpose:** Generating lifelike voice responses.
- **Called from:** `src/lib/voice/tts-engine.ts`

#### Whisper
- **Provider:** Groq
- **Purpose:** Lightning-fast STT for client audio blobs.

### External APIs
#### Piston
- **Provider:** EngineerMan (emkc.org)
- **Endpoint(s) used:** `https://emkc.org/api/v2/piston/execute`
- **Rate limits:** Handled via custom retry logic, but poses a bottleneck for production scaling.

## 6. SECURITY REFERENCE

### Auth & Authorization Model
- Supabase Auth handles identity (OAuth + Magic Links).
- Edge Middleware (`src/middleware.ts`) protects routes based on session cookies.
- RLS (Row Level Security) restricts Supabase queries to the authenticated user's ID.

### Security Checklist
- [x] No hardcoded secrets in source
- [x] All user-data routes require auth
- [x] API keys in env vars only
- [x] RLS policies on all user tables
